# 一轮新的 Markdown 与插件体验改动

更新日期：2026-10-23。

本文汇总本轮尚未提交的 MarkAtlas 改动，供后续整理 PR 使用。范围包括 Markdown、HTML/PDF 审阅、批注存储、文件导航、双文件布局、Git 文件树、样式与响应体验，并非仅修改 Markdown 格式。描述以当前合并后的代码为准；早期设计中已被替代的行为不再作为最终功能介绍。

本文不代表已经提交 commit、推送分支或创建 PR。

## 1. Markdown 语法、主题与编辑

### 语法与主题

- 扩展 Obsidian 常用语法：双向链接写法、内部嵌入、callout、任务列表及扩展任务状态、`==高亮==`、脚注、标签、数学公式和 Mermaid 图表。
- 支持内部资源、图片尺寸及嵌入内容解析；任务 Checkbox 可以切换状态并更新源码，标签可以触发搜索。
- 引入 Blue Topaz 与个人紫色 CSS 片段，并通过 PostCSS 处理选择器作用域；主题作用于 Markdown 内容，不直接覆盖整个宿主界面。
- 过滤无法正确解析的主题规则及不适用于插件的 Obsidian 装饰资源，修复正文隐藏、颜色失效、表格及图片显示问题。
- 个人紫色片段放在主题适配之后加载；阅读内容与 Live Preview 的渲染组件共享样式。
- 调整正文行距、段落与列表间距；修正表格行的列宽一致性、表头与隔行底色。

这里支持的是已实现的 Markdown/Obsidian 语法，不包含 Dataview 等第三方 Obsidian 插件的运行环境，也不声称完整复制 Obsidian。

### 最终模式与编辑行为

- Markdown 当前使用 **Preview / Source 两种模式**：Preview 是可编辑的实时预览，Source 是源码编辑。早期独立的 Edit 状态已经合并。
- HTML 保留网页 Preview 与可编辑 Source；普通代码文件使用可编辑 Source。模式按钮根据文件类型调整。
- Markdown 编辑底层使用 CodeMirror 6，局部预览由 MarkAtlas 扩展实现，并非嵌入 Codex 的原生编辑器。
- 鼠标悬停不改变内容；点击后只在光标所在的局部源码行进入编辑。列表、嵌套列表与表格按行处理，避免整块突然展开。
- 光标移走后恢复预览；多行选区内保留可编辑源码。点击位置通过源码映射定位，而非总跳到段落开头。
- 保留连续空行、撤销历史和自动保存；切换模式尽量维持滚动位置与编辑焦点。
- `Command/Ctrl + /` 切换 Markdown Preview / Source。

### 快捷键与代码高亮

- 选中文字后，`Command/Ctrl+B` 加粗，`Command/Ctrl+I` 斜体。
- 输入 `$` 包裹为行内公式；连续输入两次 `=` 包裹为高亮。已有同类包裹时可取消，操作支持撤销。
- 只读状态和输入法组合输入不触发这些文字包裹操作。
- 使用 CodeMirror 语言包、legacy modes 与 Highlight.js 扩展语言覆盖，统一采用 GitHub 浅色语法配色。
- 覆盖 Python、JSON、CSS、JavaScript/TypeScript、HTML、Java、C/C++、Rust、SQL、Shell、YAML、Go、Ruby、Swift、Lua、PowerShell 等常用语言；不自行维护各语言关键字规则。不保证任意扩展名都能准确识别。

## 2. HTML 网页预览与批注

- HTML 网页在 MarkAtlas 内的 iframe 中显示，保留 Request edits、Comment、Explanation 和评论侧栏；不再为了网页预览跳出插件到系统浏览器。
- 本地 Web Server 仅监听本机，支持相对路径的 CSS、JavaScript、图片等资源；保留项目访问边界。
- 支持选中文字批注，也支持鼠标拖框区域批注，附带截图、区域信息及可获取的文本。
- 对无法精确映射到源码的动态内容使用视觉/元素引用，不冒充准确源码位置。
- 点击空白关闭批注浮窗；尚未保存为批注的临时选区高亮随之清除。已保存批注仍可定位与重新打开。
- 移除多余的 Open in native preview 菜单项。
- 截图使用本地打包的 html-to-image；跨域资源与嵌套 iframe 仍受浏览器限制。页面布局变化时避免沿用错误的旧区域轮廓，已保存截图保留。

## 3. Comments、Explanation 与选区体验

- Comments 侧栏可以直接打开，不再必须先点击 Request edits 才显示已有内容。
- 悬浮批注框根据正文可用区域定位，避开侧栏；选区按钮及时出现，不需要等待完整文档重新渲染。
- Comment 与 Explanation 均使用 `Command/Ctrl+Enter` 提交，普通 Enter 换行，并提供提示。
- Explanation 可输入额外说明，指定解释方向；移除单独的 Explain Selection 提交按钮。
- `C` 只在非编辑预览场景作为 Comment 快捷键；可编辑模式不截获普通字母输入，也不显示冲突的快捷键提示。
- 侧栏同时收录 Comments 与 Explanation，按文件和原文位置组织。两个筛选按钮互斥，再次点击当前筛选项恢复全部显示。
- Explanation 不作为修改要求发送；Send 和 Cancel all 处理 Comments。Explanation 可单独删除。
- 点击列表记录定位对应原文；双文件模式下按当前活动面板路由定位。
- 删除操作使用垃圾桶图标；Cancel all 放在底部 Send 旁，移除底部统计旁旧的上箭头。
- 评论列表采用较轻的分隔式布局；当前合并版本的内容批注采用低干扰下划线，可直接点击标记打开记录。早期黄色/蓝色大面积高亮方案已被后续样式调整替代。
- Markdown、PDF 与 Word 的已有标记支持直接定位，减少正文末尾额外小按钮的视觉干扰。

## 4. 保存、外部修改与项目隔离

### 发送时读取最新磁盘内容

- Send 前读取磁盘最新版本，不再仅因文件版本发生变化而要求重新打开文件。
- 保留批注最初引用的原文，同时附上最新磁盘上下文；唯一匹配时更新位置，无法可靠定位时明确标记不确定。
- 当前文件没有未保存编辑时更新预览；存在草稿时保留草稿，避免无条件覆盖用户输入。
- 后台刷新在输入或批注浮窗活跃时适当暂缓，减少打断。
- 自动保存串行化并保留恢复草稿；真实冲突不会让用户失去切换文件的能力。
- 文件不存在、权限失败或宿主发送失败等真实错误仍会报告，并非忽略所有错误后假装发送成功。

### 项目内存储

打开真实项目根目录后，主体数据存放在：

```text
项目根目录/
└── .markatlas/
    ├── project.json
    └── <文档标识的 SHA-256>.document.json
```

- `project.json` 保存项目批注队列、截图、工作草稿及磁盘基线。
- `*.document.json` 保存文档工作版本、批注锚点、原文快照和修改检查点。
- 不同根目录分别读写，侧栏、统计、发送和清空操作均限定当前项目；同名文件不会混用批注。
- 浏览器本地存储保留为快速恢复层；全局数据目录仍保留批注 ID 的查找索引，供聊天中的解析工具使用。
- 未连接真实根目录的临时文件继续使用原有缓存，不猜测项目路径。
- 元数据使用临时文件加原子替换写入；拒绝 `.markatlas` 符号链接，内部数据不进入普通文件树与相关源码扫描。
- 旧缓存逐步迁移且不直接删除；双面板按各自修改的文档合并写入，避免相互覆盖批注。

项目数据隔离不等于跨机器自动同步批注；本轮双机同步的是插件代码和构建，不额外搬运用户项目内容。

## 5. PDF 与文档导航

- PDF 支持页码输入跳转、左侧缩略图与内置目录导航。
- 使用 PDF.js 解析内部跳转目标和外部链接；保留既有文本选择、区域截图与批注能力。
- 缩略图按可见范围加载，并限制渲染并发；加载时显示 Loading…，失败时显示 Preview unavailable，避免破损图片占位。
- 打开或关闭 Comments 时保留 PDF 画布位置、缩放和横向滚动，不再因侧栏变化强制重新居中或缩小。
- PDF 隐藏 Readable / Full Width 控件；其他适用文档继续使用宽度切换。
- Markdown 使用同一导航入口展示分级标题大纲，并支持跳转到对应内容。
- 文件未包含链接或书签时，不自动生成语义跳转目标；扫描 PDF 不自动 OCR。

## 6. 文件树、导航与双文件布局

- 文件树默认左侧，Comments 默认右侧；Show on left / Show on right 可切换文件树位置，工具按钮随位置移动。
- 隐藏文件可通过眼睛按钮切换显示，状态有对应图标与英文提示；内部保留目录仍按排除规则处理。
- 文件树支持把文件拖到项目内另一目录或根目录，实际移动磁盘文件；禁止覆盖同名目标并检查路径边界。移动后更新打开路径、历史与批注记录。
- 当前不支持拖动整个文件夹，也不自动改写文档内相对链接。
- Reveal in Finder 在 Finder 中显示并选中目标文件或目录。
- 原生文件选择器直接启动辅助程序，避免先等待文档渲染/保存；实际离开旧文件前仍检查保存状态。云盘或系统目录加载延迟仍可能存在。
- 顶部路径按完整路径段适配宽度，优先保留文件名；窄窗口提供文件名换行回退，恢复宽度后重新布局。
- 点击路径或文件名可在弹出目录导航中浏览文件；插件保留自己的前进/后退历史。
- 最近项目列表保存在浏览器本地存储，最多十个，显示目录名；当前版本在未打开项目或文件时展示。
- 项目搜索支持文件掩码（如 `*.md`）、匹配行预览及跳转，使用 `Command/Ctrl+F` 或对应项目搜索快捷键。它是当前替代早期独立 Find in File 浮框的入口，最多展示前 100 条匹配。
- 文件右键可选 Open on right / Open on bottom，同时显示两个文件；分隔线可拖动，文件标题可拖到不同边缘换位。
- 两个面板独立编辑、滚动和预览；关闭主面板时可将另一文件提升为主面板。只支持两份文件，不递归创建更多面板。
- 正文使用独立滚动区域，顶栏不随正文惯性滚动；侧栏与正文分别占位。

## 7. Git 变化统计与排序

- 当前目录属于本地 Git 工作区时显示增删行数，无需 GitHub 连接或远程仓库配置。
- 以 HEAD 为基准统计暂存与未暂存修改的净变化，避免重复累计；支持未跟踪文本文件和无首次提交的仓库。
- 文件和目录显示变化，顶部显示汇总；删除文件保留灰色不可打开的条目。二进制或超限未跟踪文件使用 M 提示，不伪造行数。
- 新增为绿色、删除为红色，统计右对齐；大数字使用**小写 k**，如 `+1.2k`、`-8k`，悬停及无障碍标签保留精确数字。
- Git 查询有超时与输出限制；非 Git 项目、Git 不可用或查询失败不阻断普通浏览。
- 排序支持 Name (A–Z)、Name (Z–A)、Modified (newest first)、Modified (oldest first)、File type；Folders first 独立开关。
- 使用自然数字名称顺序；目录修改时间考虑子项。排序设置保存在本地存储。
- 排序菜单与文件树位置菜单使用协调的小字号英文样式；已验证菜单为 12 px、常规字重。
- 保存后延迟刷新树统计，重新打开文件树或回到窗口时也刷新。

## 8. 样式与底层体验优化

- 工具栏多数操作使用图标加英文悬停提示，Request edits 保留文字；空状态也避免 Preview 文本挤出图标区域。
- 当前合并版本使用中性的宿主风格控件与成组工具栏；文档紫色主题与工具栏色彩分离。具体圆角以最终合并样式为准，不再沿用早期每个按钮都有独立圆框的设计。
- 选区变化按动画帧合并处理，选区按钮与完整渲染解耦，减少“先重绘高亮、再弹按钮”的等待。
- Markdown 解析结构在文档修改时更新，单纯移动光标复用结构；局部行渲染减少整块替换带来的跳动。
- 保存、项目状态写入和 Git 树刷新分别调度，避免每次输入都做完整项目刷新。
- 分屏使用带令牌和来源检查的消息桥；工作区文件操作保留路径与符号链接边界检查。
- 上述优化有代码及交互验证，但未做跨设备统一性能基准，不声称零延迟或固定毫秒响应。
