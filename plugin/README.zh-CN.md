# MarkAtlas

[English](README.md) | **简体中文**

**收集批注，让 AI 行动。**<br>
开发者：**Zihao Jing**

与 AI 助手一起阅读、理解和编辑项目文件。MarkAtlas 可以收集 Markdown、代码和 PDF 中的批注，供你统一检查，再向当前聊天发送一条简短请求，并附上独立的上下文附件。每条批注保留文件位置，截图会与对应请求放在一起。

## 安装到 ChatGPT 桌面版

MarkAtlas 已提交 OpenAI 审核。目前尚不支持通过公共插件搜索安装；如果审核通过并正式发布，就会在公共插件目录中提供。在此之前，请参阅[源码安装指南](../README.zh-CN.md#从源码安装到-chatgpt-桌面版)。

在 macOS 上下载或克隆完整仓库，安装并登录支持本地插件的 ChatGPT 桌面版，然后在仓库根目录运行：

```sh
bash install-macos.command
```

脚本会安装 Node.js 22/npm、Poppler PDF 工具和构建依赖，构建 MarkAtlas，并打开本地插件页面。在 ChatGPT 桌面版中点击 **Install（安装）**，然后打开本地聊天，请助手打开 MarkAtlas。Apple 命令行工具可能需要你先完成安装对话框，再重新运行脚本。加上 `--with-codex` 可以同时安装可选的 Codex CLI，用于后台解释；安装后请运行 `codex` 并登录。LaTeX 编译需要另行安装工具链。

仓库中的 `.agents/plugins/marketplace.json` 是指向 `plugin/` 的本地目录清单。可以分享仓库链接，让其他人下载、构建并安装自己的副本；它与公共插件目录相互独立。当前安装流程不支持 Windows 和 Linux。

## 打开文件或项目

点击 **Open file…（打开文件）** 或文件树筛选框旁的文件图标，选择单个 PDF、Markdown 或代码文件。通过宿主的文件入口打开文件时，也使用同样的流程。打开本地文件会同时连接其父文件夹，并在文件树中选中该文件。宿主文件入口会使用宿主提供的原始本地路径，即使资源 URI 本身并不直观。单个 PDF 也支持连续阅读、缩放、选区、截图批注、解释和批量发送。本地文件直接从实际路径读取，因此已连接的文本文件可以自动保存，本地 PDF 也可以在变化后刷新。

对于未暴露文件系统路径的资源附件或浏览器选择的文件，系统会使用本地工作副本。编辑该副本不会覆盖无法访问的原始文件。如果仍可通过宿主读取资源，则支持资源刷新。没有原始路径的导入资源会保留在隔离的单文件树中。本地 PDF 可以在其连接的父文件夹中查找相邻的 LaTeX 源文件。

从全局入口或当前会话入口打开 MarkAtlas。如果宿主提供了工作区文件夹，文件可能会自动显示；否则，点击文件夹图标，通过原生选择器连接文件夹。文件树只列出文件，不会上传目录；打开文件时才读取内容。

使用筛选框查找文件，点击文件夹面包屑导航浏览目录，拖动文件树边缘调整宽度。右键点击文件或文件夹名称，可选择 **Copy path（复制完整路径）** 或 **Copy relative path（复制相对路径）**，后者相对于已连接的项目根目录。对于未暴露文件系统位置的浏览器文件夹，无法复制完整路径。打开文本文件时文件树保持展开；打开 PDF 时会收起，为文档留出更多空间。

## 添加批注并发送

开启 **Request edits（请求修改）** 后，选中段落，在浮动面板中输入批注。按 **Enter** 保存，按 **Command+Enter** 换行。在可编辑文档中选择文字时，焦点仍保留在文档中，直到你点击批注输入框。

底部栏会统计文件数和批注数。将鼠标移到上方，或点击数量，即可预览待发送队列；再次点击数量可关闭预览。可以通过移除控件删除单条批注，也可以点击预览上方的 **Cancel all（全部取消）**。关闭 Request edits 会隐藏底部栏，但不会清空队列。

**Send（发送）** 会先完成待处理的自动保存，检查剩余批注，再立即提交一条简短请求。第一个上下文附件集中包含项目路径、文件信息和批注与文件的对应关系；之后每个附件包含一条编号批注，截图随对应批注发送。单文件和项目审阅使用相同的发送流程。如果发送失败，有效批注会保留，方便重试。成功发送或删除的批注会从已打开文件和缓存草稿中移除。

如果宿主没有可用的聊天输入框，MarkAtlas 会保留队列中的批注。打开目标聊天后重试 **Send（发送）**，或选择 **Send to new chat（发送到新聊天）**。发送失败不会自动切换聊天。

## 支持的工作流程

- **Markdown：** 可编辑的渲染视图和源码视图，支持表格、文字选区和批注。
- **代码与文本：** 使用 CodeMirror 编辑器，为支持的语言提供高亮，支持撤销、重做、字号调整，以及已连接文本文件的自动保存。其他 UTF-8 文本使用纯文本编辑器。
- **PDF：** 连续页面、矢量页面显示、围绕鼠标位置缩放、页面导航、已有文本的选择，以及区域截图批注。支持普通 PDF 和没有源文件的 LaTeX PDF。
- **LaTeX：** 通过 SyncTeX 或文本匹配将 PDF 位置映射到源文件，支持跳转源码，以及外部重新编译后的自动预览刷新。助手负责编辑 `.tex` 文件并调用你已安装的构建命令；插件本身不编译文档。
- **图片：** 本地预览常见图片格式。
- **Office：** 在项目树中点击 Word 和 Excel 文件，会交给宿主的原生查看器。支持的文档输入仍可使用只读 DOCX 预览；它不能编辑 Word 格式，也不保证与 Word 的分页完全一致。

**Edit（编辑）** 开关用于在 Markdown 和代码的编辑模式与只读模式之间切换。停止输入片刻后，文本修改会自动保存。保存前会检查磁盘版本，发生冲突时停止保存，避免静默覆盖外部修改。通过浏览器选择、且未建立可写项目连接的文件，只会将编辑保留为本地草稿。

## 解释功能

同一个选区可以同时保留批注和解释。切换 **Comment（批注）** 与 **Explanation（解释）** 时，各自已保存的内容都会保留；删除或发送批注，也不会移除解释。选择 **Explanation（解释）** 后，可选择 Short、Medium 或 Long，分别对应简短、中等和详细。解释直接显示在选区面板中，不会打开或切换聊天标签页。等待模型响应时，面板会提示可能需要几秒钟。支持 MCP sampling 的宿主会使用该服务；否则，本地服务通过已登录的 Codex CLI 新建临时后台会话，等待结果后显示在同一面板中。两种方式都会接收完整选区和附带截图。

可以在宿主的插件设置中选择解释模型。CLI 后备方式要求安装较新的 Codex CLI、完成登录，并有权使用所选模型。它在临时目录中以只读沙箱运行，不加载用户配置；临时提示、截图和回复会在结束后清理。如果可执行文件不在 PATH 中，可在服务环境中设置 `MARKATLAS_CODEX_PATH`。模型访问或登录失败的信息会显示在解释框中。

## 批注与文件变化

发送前，批注会跟随文本编辑更新。被删除的段落会自动失去对应批注。与旧版 PDF 绑定的截图批注会被移除，不会错误地套用到其他图片上。其他外部文件变化需要先刷新，之后才能发送剩余审阅内容。

版本检查和批注记录在内部处理。最终 AI 请求尽可能使用项目相对路径，包含当前位置、精简摘录、批注和对应图片，不会显示版本哈希或批注 ID。发送后的文件变化无法改写聊天历史；助手必须在编辑前，将引用段落与当前文件核对。

## 环境要求与访问范围

- 支持 MCP Apps 和原生聊天草稿消息的兼容桌面宿主。后台解释需要 MCP sampling 或已登录的 Codex CLI。
- 从源码运行需要 **Node.js 22 或更高版本**。
- 附带的原生文件夹选择器需要 **macOS**，构建该辅助程序需要 Swift 命令行工具。
- PDF 审阅需要 **Poppler** 工具（`pdftotext`、`pdftocairo` 和 `pdftoppm`）。SyncTeX 可以改善 LaTeX 源码映射；编译则需要你自行安装 LaTeX。

读写范围仅限于宿主提供的文件夹、用户明确连接的文件夹，以及明确打开的本地文件所在的父文件夹。没有本地路径的导入资源保持隔离。文件树会跳过 `.git`、`node_modules`、`.codex`、`.agents` 和 `.aws`，最多列出 5,000 个文件。文本读取和保存上限为 5 MB；PDF 上限为 50 MB、300 页，提取文本上限为 5 MB。没有文本层的扫描 PDF 不支持文字选择，请使用截图批注。

在存储可用时，草稿会保存在本地。发送审阅上下文会将批注、摘录和截图共享给聊天宿主；解释请求也会共享所选内容。存储容量限制，尤其是截图占用，可能影响重新加载后的草稿恢复。

## 本地开发

在仓库根目录执行：

```sh
npm ci --include=dev --prefix plugin
npm run build --prefix plugin
npm run preview --prefix plugin -- /path/to/project
```

打开 **http://127.0.0.1:4174/**。开发预览支持原生选择器和项目文件访问，但聊天发送是模拟的。预览中的 Send 操作不会真正提交模型请求；解释操作则会使用本地 Codex CLI，确实请求模型响应。

运行插件检查：

```sh
npm test --prefix plugin
```

仓库根目录的 `npm start` 启动的是早期独立浏览器原型，端口为 4173。当前 MarkAtlas 开发请使用上面的插件预览。

为保持兼容，软件包保留原有内部插件和工具标识；对外显示名称为 **MarkAtlas**。

## 打包桌面版本

在已安装开发依赖和 Swift 工具的 Apple Silicon Mac 上运行：

```sh
python3 plugin/desktop-pdf.py --fetch-sources
npm run pack:desktop --prefix plugin
```

这会生成 `releases/markatlas-VERSION-macos-arm64.zip` 及其 SHA-256 校验文件。分发包包含 Node、服务端 JavaScript 依赖、查看器、原生选择器、Poppler 可执行文件和库、对应 PDF 组件的源码与构建配方，以及第三方声明。打包流程会解压 ZIP，检查 MCP 启动、工具发现、查看器加载、文件读取与保存、PDF 文本提取，以及 SVG/PNG 渲染。接收者不需要 npm，也无需执行构建，但仍需通过宿主支持的本地插件流程安装；仅解压 ZIP 不等于安装插件。

该分发包仅支持 macOS arm64，并附带 Poppler；解释功能需要宿主 sampling 或已登录的 Codex CLI。它是开发和分发用的构建产物，生成分发包不等于已通过公开发布审核。发布者验证、本地 MCP 提交权限、上架链接、PNG 图标、审核材料和提交门户检查等要求仍需满足。修改附带的 Node 版本时，请在打包前将该版本的官方许可证放入 `plugin/licenses/node-vVERSION.txt`。

连接工作区时，MarkAtlas 会自动打开根目录下的 README。匹配不区分大小写，优先顺序为 README.md、README.markdown、README、README.txt、README.rst。如果根目录没有 README，则保留空文件提示，不会自动选择子目录中的 README。常规文件树刷新会保留当前文件。
